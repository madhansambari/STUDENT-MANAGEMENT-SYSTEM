# 1. PROJECT INTRODUCTION

The Student Management System is a relational database project developed using MySQL. It is designed to organize and maintain academic information about departments, courses, students, subjects, examination marks and student attendance.

The database provides a centralized structure for storing related academic records and retrieving useful information through SQL queries and reports.

# 2. PROBLEM STATEMENT

Educational institutions need to maintain student details, course enrolments, subject information, examination results and attendance records.

When these records are maintained separately or manually, it can become difficult to find information, avoid duplicate data, connect students with their courses and subjects, and prepare academic reports.

Some common problems include:

- Student information being repeated across separate records.
- Difficulty finding students enrolled in a particular course.
- Difficulty summarizing examination marks.
- Difficulty reviewing student attendance.
- Time-consuming preparation of department-wise and course-wise reports.

The Student Management System addresses these problems by organizing academic information in a relational MySQL database.

# 3. PROJECT OBJECTIVES

The main objectives of this project are:

1. Store and manage student information in a structured database.
2. Maintain department and course details.
3. Associate courses with departments and students with courses.
4. Maintain subject details for each course.
5. Record examination marks for students and subjects.
6. Record daily attendance for each student.
7. Retrieve information using basic SQL queries.
8. Analyse data using aggregate functions, GROUP BY and HAVING.
9. Combine related information using joins and subqueries.
10. Create reusable views, stored procedures and stored functions.
11. Use triggers to maintain audit records when marks are inserted or updated.
12. Demonstrate transaction control, indexes and query-plan analysis.
13. Generate academic and management reports.

# 8. DATABASE REQUIREMENTS AND TABLE DESIGN

The database name is:

`student_management_system`

The database contains six core tables.

## 8.1 Departments Table

**Table Name:** `departments`

**Purpose:** Stores department information.

Main columns:

- department_id – Primary Key
- department_name – Department name
- department_code – Unique department code
- office_location – Department location

## 8.2 Courses Table

**Table Name:** `courses`

**Purpose:** Stores course information.

Main columns:

- course_id – Primary Key
- course_name – Course name
- course_fee – Course fee
- department_id – Foreign Key

## 8.3 Students Table

**Table Name:** `students`

**Purpose:** Stores student personal and academic information.

Main columns:

- student_id – Primary Key
- first_name – Student first name
- last_name – Student last name
- age – Student age
- gender – Student gender
- phone – Student phone number
- email – Student email address
- course_id – Foreign Key
- admission_date – Admission date
- student_status – Student status

## 8.4 Subjects Table

**Table Name:** `subjects`

**Purpose:** Stores subject information for each course.

Main columns:

- subject_id – Primary Key
- subject_name – Subject name
- subject_code – Unique subject code
- course_id – Foreign Key

## 8.5 Marks Table

**Table Name:** `marks`

**Purpose:** Stores examination marks obtained by students.

Main columns:

- mark_id – Primary Key
- student_id – Foreign Key
- subject_id – Foreign Key
- exam_type – Examination type
- marks_obtained – Marks obtained
- exam_date – Examination date

## 8.6 Attendance Table

**Table Name:** `attendance`

**Purpose:** Stores daily attendance information.

Main columns:

- attendance_id – Primary Key
- student_id – Foreign Key
- attendance_date – Attendance date
- attendance_status – Present, Absent or Late

# 9. DATABASE RELATIONSHIPS

The database uses the following relationships:

1. Departments to Courses – One department can have many courses.
2. Courses to Students – One course can have many students.
3. Courses to Subjects – One course can have many subjects.
4. Students to Marks – One student can have multiple marks records.
5. Subjects to Marks – One subject can have multiple marks records.
6. Students to Attendance – One student can have multiple attendance records.

The marks table records the relationship between students and subjects for particular examination types.

# 10. DATABASE CONSTRAINTS

The project uses the following database constraints:

**PRIMARY KEY:** Uniquely identifies each record in a table.

**FOREIGN KEY:** Establishes relationships between related tables.

**UNIQUE:** Prevents duplicate values in selected columns.

**NOT NULL:** Ensures mandatory fields contain values.

**DEFAULT:** Assigns default values when a value is not supplied.

**CHECK:** Validates values based on specified conditions.

**AUTO_INCREMENT:** Generates unique numeric identifiers automatically.

These constraints help maintain data accuracy and consistency.

# 14. DATABASE NORMALIZATION

The database is designed using normalization principles to reduce unnecessary data duplication and maintain consistency.

## First Normal Form (1NF)

Each column stores individual values. Repeating groups are avoided.

## Second Normal Form (2NF)

Non-key attributes are stored with the key that identifies their records. The core tables use single-column primary keys.

## Third Normal Form (3NF)

Department and course information are maintained in separate tables rather than being repeatedly stored in student records.

This structure helps reduce data redundancy and improve database consistency.
